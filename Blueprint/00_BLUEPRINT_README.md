# Blueprint

This folder is the project contract.

It defines:
- product identity
- architecture
- implementation boundaries
- current scope
- execution rules for the coding agent

Blueprint is not a note collection.
Blueprint is the source of truth for project structure and growth.

If generated code conflicts with Blueprint, the code must be corrected.
Blueprint must not be silently ignored.

## Current project direction

We are building a desktop-first parametric CAD Studio with an integrated engineering assistant.

The product is intended to grow from:
- early MVP / toy stage
to:
- serious engineering tool

## Core principles

- Desktop-first
- Local compute first
- Structured geometry first
- Assistant as augmentation, not replacement
- No fake UI
- No dashboard/SaaS patterns
- No organic sculpting in the current stage
